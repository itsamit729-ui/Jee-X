# Learning follow-up

Students can open **Explore → Mistakes & revision** (`/learning`). Wrong and skipped answers from the latest responses to up to 500 recent questions become revision cards. Class questions require active membership, an assigned submitted result and released solutions. A correct subsequent normal attempt retires the card. Eight-question untimed sessions grade on the server, reveal explanations only on submission and schedule successful retrieval at 3, 7, 14 then 30 days; misses return after one day. Revision does not create ranked attempts, mastery records or coins. Sessions resume for one day; unsaved choices live only on the current screen. Changed keys/source evidence invalidate stale sessions.

Teachers use **Syllabus & improvement** to mark covered chapters and inspect their own class results. Students see those covered chapters in their learning notebook. **Only taught chapters** in the paper builder uses the intersection across selected classes and rejects empty coverage. Generation blueprints save exam, chapter, section, level, class and reference-paper settings; locks and temporary question exclusions are not persisted. Up to 100 blueprints per teacher.

Class improvement compares marks percentages on the last two assigned tests, including linked reviewed OMR results. Different tests can differ in difficulty, so this is not a calibrated ability measure. Below-70%-accuracy topics feed personal remedial assignments. Teachers explicitly select up to 50 students, a question count and publish. Each student receives only their own fresh questions, a two-minute-per-question timer (minimum ten minutes), seven-day deadline and solution release at that deadline. Insufficient-bank or insufficient-evidence students are reported as skipped. Repeating a publish request does not duplicate previously published assignments. Standalone offline scan results are not included in this class-assignment report.

**Ask teacher** on released assignment questions opens a private question doubt. Teachers reply in **Question doubts**. Students can consent to class sharing; sharing is off by default. Shared threads omit the account name and are readable only by active assigned classmates who have submitted and reached solution release. The UI asks students to leave personal details out of shareable text. This release supports text/LaTeX questions and replies, not photo uploads or paid AI answers. In-app notifications link to new doubts and replies. At most 20 new doubts per student per day; lists show up to 100 threads.

Deploy frontend and backend together. Five new tables (`revision_cards`, `revision_sessions`, `teacher_taught_chapters`, `teacher_blueprints`, `question_doubts`) are created by existing startup metadata creation. Existing tables and attempt history are unchanged. Revision evidence IDs deliberately have no foreign-key constraint because key corrections rebuild response rows. No additional service, scheduled worker or paid API is needed.

### Optional AI paper creation

Clicking **Create a paper** opens **Describe with AI** directly, with no setup wizard. **Create manually** opens the existing builder. In the AI chat, teachers describe a question count, subject mix, chapters, difficulty target, or available PYQ year/shift. The existing manual methods remain available. Complete requests automatically create a finalized, teacher-owned paper and show **Download paper PDF** and **Download OMR PDF**, including matching A/B downloads when sets are requested. Nothing is assigned to students. The saved paper remains available in the library; duplicate it to edit.

Missing counts, ambiguous shifts, unavailable topics and bank shortfalls return a follow-up in the same conversation. The AI entry has no exam selector or preset duration. The teacher supplies the exam, question count, subjects/chapters or paper scope, and duration in the chat. Missing required fields are requested together and prior replies are retained. Intent classification blocks unrelated messages from creating a paper. Balanced difficulty, a single set and exam/subject-appropriate uniform marking are defaults; explicit requests override them. Mixed-subject MHT-CET papers require a uniform mark value when subject-specific marks cannot be represented. No mandatory review, saving or finalising clicks follow a successful request. AI interpretation is approximate; the saved paper can still be inspected or duplicated.

`POST /api/teacher/papers/ai-create` uses a client request UUID. Retrying the same request returns the same teacher-owned paper without another AI call. A row lock serializes persistence after generation, with a second lookup to prevent concurrent duplicate saves. Copies do not inherit the request key. The legacy `/ai-draft` endpoint remains read-only for older clients.

Set `GROQ_API_KEY` on the main web service. `TEACHER_AI_ENABLED=false` disables only AI creation. `TEACHER_AI_MODEL` defaults to `openai/gpt-oss-20b`. No new database migration is needed. The provider receives the request, supplied defaults and compact published chapter/paper metadata, never question text, answer keys or student data. One bounded provider call per conversational turn, with a 1,600 completion-token cap, timeouts and no automatic retries. Durable counters limit each teacher to 3 calls/minute and 30/day, and the app to 100/day. Provider token quotas can be reached sooner; errors leave existing manual selections intact. Usage totals are logged without prompts or credentials.

Question-paper PDFs render on demand in the browser with KaTeX, diagrams, page numbers and saved snapshot order. The PDF dependencies load only on download. This avoids browser/video rendering on the web server. Current diagram URLs use static delivery with one bounded retry for transient failures. Legacy-hosted bank URLs can resolve through an authenticated, snapshot-indexed diagram route, which reads only local bundled images and rejects traversal or arbitrary remote fetches. Missing diagrams report the affected question and HTTP failure rather than silently disappearing. Question papers exclude answer keys and solutions. OMR PDFs use the existing authenticated server download and the same saved paper/set order. Re-downloading does not call AI. Difficulty uses bank tags; exact-paper coverage and original ordering are not certified.
